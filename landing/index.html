Encrypted messages, delivered by the same lookup that finds google.com.

DNS Mesh Protocol moves end-to-end encrypted messages between two people over plain DNS. The recipient looks you up the same way every computer looks up any other domain — through the recursive chain that already runs on your network, with no app store, no relay company, and no account to create.

Every messaging product you’ve used puts a single company in the middle of every conversation. They sit on the wire. They can be subpoenaed, breached, blocked, deplatformed, or simply turned off. DMP replaces that company with the DNS recursive chain, which has no single owner and which every device on the internet trusts implicitly all day, every day. If DNS resolves on your network, DMP works on your network.

Three TXT lookups carry an entire conversation.

The first lookup pulls the recipient’s long-term Ed25519 and X25519 public keys from a TXT record under their domain. The second pulls the encrypted mailbox slots they’re currently advertising. The third pulls the ciphertext chunks themselves. Plaintext is derived locally; the recursive chain only ever sees opaque bytes routed through whatever caches the message happens to traverse. 

sender                  recursive DNS                  recipient
   │                          │                            │
   │   TXT _dnsmesh-id.bob.dmp.io      │                            │
   ├─────────────────────────►│ ──── cached, like any ────►│
   │   pubkey + prekey                │                            │
   │◄─────────────────────────│                            │
   │                          │                            │
   │   DNS UPDATE  +  TSIG signed     │                            │
   ├─────────────────────────►│ ────── authenticated ─────►│  store ciphertext chunk
   │                          │                            │
   │                          │   TXT _dnsmesh-chunk-7f.…     │
   │                          │◄───────── plain ───────────┤
   │                          │   ciphertext                  │
   │                          │ ──────────────────────────►│

Reads are open and writes are signed. That asymmetry is what removes the gatekeeper. Anyone, on any network, can resolve any user’s identity, mailbox slots, and chunks — the records are public TXT entries served by ordinary DNS. Mutations, on the other hand, are RFC 2136 DNS UPDATE packets signed with an RFC 8945 TSIG key issued per user. One HTTPS call mints the key on first registration; after that, no HTTPS hop is involved in publishing identity, refreshing prekeys, or delivering chunks. Every node in the federation accepts those updates from any user whose key it knows about, which means no single node is canonical and none of them can hold a conversation hostage.

Five minutes against the public node.

The reference node at dnsmesh.io is open registration and serves the bootstrap-seed and claim-provider roles other nodes default to. Self-hosting gets the same capabilities through deploy/native-ubuntu/install.sh; both modes interoperate over DNS, because the wire is the contract. 

terminal# install
pipx install dnsmesh

# the passphrase derives your Ed25519 + X25519 keypair via Argon2id.
# lose it and you lose the identity. there is no recovery.
read -rs DMP_PASSPHRASE; export DMP_PASSPHRASE

# mint a TSIG key, then publish your identity over signed DNS UPDATE
dnsmesh init alice --domain dmp.dnsmesh.io --endpoint https://dnsmesh.io
dnsmesh tsig register --node dnsmesh.io
dnsmesh identity publish
dnsmesh identity refresh-prekeys

# talk to someone who’s already published
dnsmesh identity fetch bob@dmp.dnsmesh.io --add
dnsmesh send bob@dmp.dnsmesh.io "hi bob"
dnsmesh recv

Curious what a node is publishing right now? dig _dnsmesh-heartbeat.dmp.dnsmesh.io TXT +short returns the live heartbeat. A signature-verified directory of every node currently advertising on the public DNS chain is rebuilt every thirty minutes from a federated seed list, and lives at ovalenzuela.com/DNSMeshProtocol/directory.

The protocol is not yet audited. Wire format, federation, identity and key rotation, multi-tenant auth, and the formal spec have all shipped, but the cryptographic audit hasn’t. Don’t route confidentiality-critical traffic through DMP yet. Read SECURITY.md before you trust this with anything that matters.
